# How the Pieces Fit

The mechanisms that keep this repo's skills, agents, rules and hooks correct,
and where each one is documented. One paragraph per piece; the linked file owns
the detail. This page lives in `docs/` rather than in `CLAUDE.md` so it costs
nothing on every turn (#2838 A-7).

## Authoring surface

- **Plugins** hold the skills, agents and hooks that ship to users. Their
  layout and manifest schema are in
  [`.claude/rules/plugin-structure.md`](../.claude/rules/plugin-structure.md);
  the user-facing index is [`PLUGIN-MAP.md`](PLUGIN-MAP.md) (task-oriented
  navigation) and [`CATALOG.md`](CATALOG.md) (generated by `just catalog`
  from `marketplace.json` and the plugin directories).
- **Rules** in `.claude/rules/` steer work inside this repo. The `CLAUDE.md`
  Rules table lists each one; [`rules-map.md`](rules-map.md) groups them and
  names the owner of each shared fact. Long-form companions of the unscoped
  rules live in [`docs/rules/`](rules/).
- **Principles**: [`PRINCIPLES.md`](PRINCIPLES.md) states the methodology the
  rules, skills and hooks embody, and names which ones embody each principle.

## Enforcement, from the moment of the edit to the scheduled audit

- **Hooks** act inside a Claude Code session, on the tool call itself. They
  live in many plugins, not only `hooks-plugin`; `plugin.json` wires each set
  (list them with
  `jq -r 'select(.hooks) | input_filename' */.claude-plugin/plugin.json`).
  Events and schemas:
  [`.claude/rules/hooks-reference.md`](../.claude/rules/hooks-reference.md);
  when a hook may block rather than nudge:
  [`.claude/rules/hook-block-vs-nudge.md`](../.claude/rules/hook-block-vs-nudge.md).
- **Check scripts** (`scripts/check-*.sh`, `scripts/check-*.py`) are the
  deterministic guards. Each emits the `KEY=VALUE` / `STATUS=` contract in
  [`.claude/rules/structured-script-output.md`](../.claude/rules/structured-script-output.md),
  and most have a self-test under `scripts/tests/` that
  `scripts/run-skill-script-tests.sh` discovers. A bug fix adds a check per
  [`.claude/rules/regression-testing.md`](../.claude/rules/regression-testing.md)
  and records it in the [regression ledger](regression-ledger.md).
- **Pre-commit** (`.pre-commit-config.yaml`) runs a subset of those checks on
  the files a commit stages, including the always-loaded context budget
  (`scripts/check-context-engineering.py`).
- **CI** (`.github/workflows/`, catalogued in
  [`.github/workflows/README.md`](../.github/workflows/README.md)) runs the
  whole-repo gates. `Plugin: PR checks` reports the required `compliance`
  check on every pull request; `Test: Skill scripts` runs the self-test
  suites; `Plugin: Scheduled audits` runs the Layer 1 drift checks monthly
  and files issues from them ([`audits/README.md`](audits/README.md) records
  the audit cadence).
- **Releases**: release-please reads conventional commit subjects and PR
  titles to version each plugin
  ([`.claude/rules/conventional-commits.md`](../.claude/rules/conventional-commits.md),
  [`.claude/rules/release-please.md`](../.claude/rules/release-please.md)).

## Decision records

- **ADRs** in [`adrs/`](adrs/README.md) record why the repo is structured as
  it is. PRDs and PRPs sit beside them in `prds/` and `prps/`, managed by the
  constrained blueprint setup described in
  [`blueprint/README.md`](blueprint/README.md).
- **Audits** of these docs are kept as dated findings files in
  [`audits/`](audits/README.md).
