| Two PostToolUse cue hooks — `hooks-plugin/hooks/bash-antipatterns-teach.sh` and `blueprint-plugin/hooks/blueprint-structural-cue.sh` — emitted `hookSpecificOutput.updatedToolOutput` as a JSON **string** (`jq -n --arg out …`). The harness validates that field against the **tool's own output schema**, which is an object, so it rejected every emission (`Invalid input: expected object, received string`, `"path": []`) and silently fell back to the original output. Both hooks were **silent no-ops** — 29 discarded outputs over 50 transcripts / 7.5 days. Neither script errored and both ran in ~100ms, so nothing surfaced. The belief was written into a version comment ("Claude Code 2.1.121+") rather than pinned by a test, and **both existing suites pinned the broken shape**: `test-bash-antipatterns-teach.sh` fed a `tool_response` **string** the harness never sends and asserted mere *presence* of `updatedToolOutput`, while `hooks/spec/blueprint_structural_cue_spec.sh` asserted "output should include updatedToolOutput" — and that ShellSpec suite **never ran anywhere** (shellspec is not installed, not in CI, not in any recipe, and `spec/` matches no glob in `run-skill-script-tests.sh`). | Bash has a natural free-text field, so the teach hook now reads `.tool_response` as an **object** and emits `$orig + {stdout: $augmented}` — overwriting exactly one field of the harness's own object and inventing no keys (a union of invented keys would be a fresh rejection under a strict schema, with the same silent-fallback failure mode). Write/Edit has **no** free-text field — `content` is the file's actual content, so a cue banner there would make the model believe the banner was written to disk — so `updatedToolOutput` is the wrong mechanism for that event entirely: the blueprint cue switched to the `{"decision":"block","reason":…}` channel that `code-quality-preflight-cue.sh` already uses successfully for the same event, with `continueOnBlock: true` added to **both** `hooks.json` registrations. That config half is not optional: `decision:block` without it **ends the turn**, converting a silent no-op into an active regression on the first structural edit of every session. | `hooks-plugin/hooks/test-bash-antipatterns-teach.sh` (extended) and `blueprint-plugin/hooks/test-blueprint-structural-cue.sh` (new, replacing the never-run ShellSpec suite; both auto-discovered by `run-skill-script-tests.sh`'s `*/hooks/test-*.sh` glob).
