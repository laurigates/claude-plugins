| `hooks-plugin/hooks/test-bash-antipatterns.sh` builds throwaway sandbox repos with `git -C "$(mktemp -d)" init` / `git config`. When run under an **injected absolute `GIT_DIR` / `GIT_WORK_TREE`** — exported by an agent papering over a `core.bare=true` worktree, or inherited from the pre-commit hook's environment — those vars OVERRIDE `git -C "$sandbox"`, so the ops target the **real shared `.git`** instead of the throwaway dir, writing `core.bare=true` and a junk `[user]` / `[commit]` identity into the shared config. DISTINCT vector from the empty-`mktemp -d` case (#1692, which `check-git-sandbox-guards.sh` guards): here the sandbox path is correct but the inherited env hijacks it. Observed 2026-06-21 flipping the shared checkout to bare mid-run, breaking ~35 sibling worktrees; PR #1736 had to commit with `--no-verify` to avoid re-triggering the leak through the pre-commit hook. The pre-commit hook's *own* environment is itself an instance: it exports `GIT_DIR` + an absolute `GIT_INDEX_FILE`, so a partial `unset GIT_DIR GIT_WORK_TREE` still leaves the sandbox `git commit` pointed at the real index ("invalid object" / "index file smaller than expected"). | The suite never neutralized inherited git context. The fix unsets the FULL family — `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE GIT_OBJECT_DIRECTORY GIT_COMMON_DIR GIT_NAMESPACE GIT_PREFIX` — at the top of `test-bash-antipatterns.sh`, which protects every git op in the suite AND the hook subprocesses it spawns (they inherit the cleaned env), for current and future ops alike. | `hooks-plugin/hooks/test-bash-antipatterns-git-env-isolation.sh` stands up a throwaway "real" repo, snapshots its `.git/config`, runs the suite with `GIT_DIR`/`GIT_WORK_TREE` exported at it, and asserts the config is byte-identical afterward (plus `core.bare` not flipped, seeded `user.email` intact). Wired into `.pre-commit-config.yaml`. | issue #1745 |
