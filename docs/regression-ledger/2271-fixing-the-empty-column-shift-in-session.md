| Fixing the EMPTY-column shift in `session-survey.sh` (TAB is an IFS *whitespace* character, so `IFS=$'\t' read` collapses a run of tabs and an empty field shifts every later column left) introduced a **second** shift of the same class. The delimiter moved from TAB to **US (0x1F)** and the projections moved from `@tsv` to `join($us)` — but **`@tsv` escapes `\t`, `\n`, `\r` and `\\` by construction, and `join()` escapes nothing**, while the accompanying `gsub` stripped only tabs. So a task whose description or annotation contained a **newline** split one row into two and shifted every later column: a task with a 2-line description emitted `TASK_1_DESC=line one` plus a phantom `TASK_2_UUID=line two` whose `TASK_2_ACTIVE` held the modified stamp. In the all-projects fallback rows the damage is worse — the row count is read from the emitted rows, so the task **vanished from the digest entirely** (`RECENT_TASK_COUNT` short by one), which is the same silent-zero failure #2271/#2232 were filed about, reintroduced by their own fix. A literal US byte in the content is the identical hazard. | Strip every byte that can break a row, in all four projections (recent-task feed, task-detail description, task-detail annotations, stale-elsewhere feed): `gsub("[\\t\\r\\n\\u001f]";" ")`. The `\u001f` escape is the delimiter itself — a US byte arriving in task text is indistinguishable from a column boundary, so content-sanitising it is what makes `join($us)` safe at all.
