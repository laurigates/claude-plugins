| PR #2114 ported `bash-antipatterns.sh`'s read detectors from regex to an `ast-grep` structural classifier and, as an unintended side effect, **widened** the `cat`/`head`/`tail` block from "a bare read as the whole command" (the pre-#2114 `^\s*cat\s+…` + "no pipe anywhere" scope) to "a bare read **anywhere** in a compound command". The AST rules matched any `command` node not inside a `pipeline`, so `cd repo && git log -3 && cat package.json`, `ls dir/; head -20 file`, and `echo "===" && cat -n file` all began blocking. W31 friction: same-session repeat-block rate **15.2% → 46.3%** (3.0× above a stable six-reading 6.3–20.0% band), 70 events / 41 sessions, ~30% of all friction events that week; per-session prevalence 21.6% → 68.3%. Of 72 recovered blocked commands ~47 (65%) did not begin with `cat`/`head`/`tail`. The repeat rate is the diagnostic: a bare `cat f.md` has a one-to-one `Read(file_path=…)` substitution, a compound diagnostic has **none** — the agent must split one Bash call into a Bash call plus N `Read` calls and re-plan, so it re-attempts a variant and is re-blocked in the same session. | The AST rules carried no positional constraint; `not: { inside: { kind: pipeline } }` was the only scope gate, and a compound command's arms are `list` children, not pipeline stages. Fixed by remedy (a) of #2148 (narrow, not demote — the block sat happily at 6–20% at its pre-#2114 scope, so the minimal correct action is to revert the widening rather than retire a working steer): `cat-read`, `head-tail-read`, and `task-output-read` now require `inside: { kind: program }` **plus** `nthChild` position-1 forward *and* reverse with `ofRule: { not: { kind: comment } }` — i.e. the read is the **sole statement** of the parsed program, with a trailing `# comment` excluded from the sibling count so `cat f.md  # notes` still fires. The now-redundant `not: { inside: { kind: pipeline } }` clause was dropped (`inside: { kind: program }` subsumes it). The three **write** detectors (`cat-write`, `echo-printf-write`, `sed-inplace`) keep their original scope — they guard file mutation, not context budget. | `hooks-plugin/hooks/test-bash-antipatterns.sh` "read block fires only when the read is the WHOLE command (#2148)" block replays the issue's differential-reproduction table: six compound shapes recovered from W31's blocked events must exit 0 (incl. the `git fetch; git status \| head -3; …; head -20 f; ls dir` preflight command that motivated the fix, and `sleep 5 && cat …/run.output`), while GUARD rows pin that every bare whole-command read still exits 2 (`cat`, `head -50`, `tail -50`, a task-output read, and a bare read carrying a trailing `# comment`), and that the write detectors still fire inside a compound command. Two pre-existing rows were flipped to the new scope with the reason inline (the `sleep 5 && cat …output` message assertions moved to the bare form; the #1900 `cat x && ssh host …` row now expects 0, with its real invariant — that a bare local `cat` is still classified as a local command node — pinned by a new adjacent row).
