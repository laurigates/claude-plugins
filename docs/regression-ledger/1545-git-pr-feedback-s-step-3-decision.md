| `git-pr-feedback`'s Step 3 decision table was framed around suggestions being mostly correct (`fix is correct → accept`; `fix needs adjustment → variant`) and never foregrounded **verifying the reviewer's claim against source / live state before accepting** — which matters most for automated reviewers (Gemini Code Assist, Copilot), whose suggestions are frequently confidently-wrong. In one session 3 of ~6 Gemini findings were wrong and only verification (driven by a user-global rule, not the skill) caught them; each was correctly refuted with evidence. | The skill had no "verify before accepting" step and no `refuted` action in the decision table, so the discipline lived outside the skill. The fix adds verification prose (independently verify bot/automated-reviewer claims against the actual source/live system/docs before acting) and a `Refuted` decision row (reply with the refutation + evidence, do not change code). The semantic invariant is that the verification prose and the refuted action survive bulk edits. | `plugin-compliance-check.sh` `check_skill_body()` — for `git-pr-feedback`, asserts the SKILL.md body retains both `automated reviewer` (verification prose) and `Refuted` (the decision-table action). Dropping either would silently restore "apply bot suggestions on trust". | issue #1545 |
