| `scripts/tests/test-agentic-audit-precompute.sh` passed locally and failed on the GitHub runner, on the one assertion that proves the stale list is populated (`FAIL: the 400-day-old skill appears in the stale list`). Its `section()` slicer passes boundary headings as awk regexes, and the stale-list boundary was written `'^## Skills with stale reviews \(>90 days\):$'`. **A backslash-escaped paren is undefined in POSIX awk**: the runner's mawk warns `escape sequence \`\(' treated as plain \`('` and then reads the parens as a GROUP, so the heading never matches, that section slices EMPTY, and the assertion fails. Newer mawk (1.3.4 20240123, on the dev box) tolerates the same input, so the local pass was a false negative — the two `awk: warning:` lines in the CI log were the only tell, and they are easy to read as noise beside a test failure. The deeper defect is that an empty slice is **silently satisfying**: every "must NOT contain" assertion over that section passes vacuously, so a mis-slice weakens the suite in a direction no failure reports. | Bracket expressions (`[(]>90 days[)]`) — unambiguous in POSIX ERE, no escape, no flavour-dependent behaviour — with the reasoning recorded at the line. Every other boundary in the file was already paren-free, which is why only this one section broke. | Two guards, since the fix and the class need different ones. The boundary itself is pinned by the existing assertions (an empty `stale_section` fails them). The CLASS is pinned by a new loop asserting all four sliced sections are **non-empty** before any assertion runs, failing with `FAIL: <name>_section sliced empty — a boundary heading did not match.` and exit 1 — so a future mis-slice reports the cause instead of a confusing downstream failure, and the vacuous-pass direction is closed.
