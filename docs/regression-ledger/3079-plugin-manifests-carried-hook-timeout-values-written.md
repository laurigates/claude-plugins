| Plugin manifests carried hook `timeout` values written as milliseconds (`5000`, `15000`, `60000` across hooks-plugin, blueprint, code-quality, configure, git, health, kubernetes and taskwarrior), but Claude Code reads the field as seconds (5000 s is 83 min). Since `onFailure: "block"` (#3077) a safety hook is bounded only by its timeout, so a budget that never fires could hang a session. All values converted to seconds (floor 5; `branch-protection`/`repo-deletion-safety` 15, `external-pr-merge-guard` 20). `scripts/check-hook-timeout-units.sh` fails any `timeout` >= 1000 in `*-plugin/hooks.json`, `hooks/hooks.json` and inline `plugin.json` hooks; `scripts/tests/test-check-hook-timeout-units.sh` (8 assertions) covers each file shape, the threshold, second-scale values and an empty tree, and the guard reports 27 `ms_timeout` issues against the `origin/main` hooks-plugin and blueprint-plugin manifests | #3079 |
