| `taskwarrior-plugin/skills/task-add` reported only the numeric ID after `task add` (`Created task 141.`). Taskwarrior numeric IDs are a display index over *pending* tasks and shift down by one whenever any other task completes (often in a parallel session). A session that created task 141, then 30 min later ran `task 141 annotate ...`, silently annotated an unrelated task whose ID had drifted — requiring a denotate + UUID-lookup recovery. The skill had no ergonomic to capture the stable UUID at create time. | The skill's Step 5 (create) and Step 6 (report) emitted only the numeric ID. The fix resolves the immutable UUID via the `+LATEST` virtual tag (`task +LATEST _get uuid`) as a separate Bash call and surfaces it in the report so downstream annotate/modify/done address the task by UUID. | `plugin-compliance-check.sh` `check_skill_body()` — for `task-add` specifically, asserts the SKILL.md body contains the literal string `task +LATEST _get uuid` (proves the UUID-emit survives future bulk edits) | issue #1417 |
