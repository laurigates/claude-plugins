| `scripts/run-skill-script-tests.sh` printed `PASS=<file>` for a test that **SKIPped**, so a gate whose dependency was absent on the runner was indistinguishable — in the CI log and in the `TOTAL=`/`FAILED=` roll-up — from a gate that ran and passed. `foundryvtt-plugin/skills/foundryvtt-module-scaffold/scripts/tests/test-template-parity.sh` (the acceptance gate for carrying `scaffold.py` **and** its cargo-generate port, #2205) had therefore **never once executed in CI**: `.github/workflows/test-skill-scripts.yml` installs `ast-grep` and `uv` precisely so their gates run but installed nothing for `cargo-generate`, so the SKIP branch was the only branch CI ever took. Two independent causes, either alone sufficient — the workflow's path triggers also matched no template file (`*-plugin/templates/**`), so a PR editing **only** the template, exactly the divergence the parity test exists to catch, would not run the workflow at all. Verified: 9/9 parity assertions pass when cargo-generate is actually present, so the gate was correct all along — it simply never ran. | Three fixes. (1) The workflow installs cargo-generate from the **prebuilt release tarball** (a `cargo install` compiles several hundred crates, minutes per run, for one test), cached and version-pinned via a new `renovate.json` customManager for annotated `<TOOL>_VERSION:` env pins in workflow files. (2) `*-plugin/templates/**` added to both the `pull_request` and `push` path lists — kept generic rather than foundry-specific, since other plugins will grow template directories (#2224). (3) The runner classifies a SKIP as its own outcome: `SKIP=<path>`, `PASSED=`/`SKIPPED=`/`FAILED=` counters, a `SKIPS:` block carrying each reason, and `STATUS=WARN` so a run with skips is never silently `OK`. Detection is "exited 0 and every **non-indented** non-empty line is a `SKIP:`/`SKIP -` notice", which covers both punctuation conventions in the corpus and the indented `Install: …` continuation line `test-bash-antipatterns.sh` emits, while leaving a **partial** skip inside an otherwise-executing suite a PASS. Tests that must genuinely run are **declared** in `scripts/required-to-run-tests.txt` (a skip there is ERROR/exit 1, as is a listed path matching no discovered test) — a blanket fail-on-any-skip would be red on arrival for taskwarrior/lizard and get disabled. | `scripts/tests/test-run-skill-script-tests.sh` (40 assertions) is SEMANTIC: it **executes** the real runner against planted fixture trees and asserts on its structured output — a grep for `SKIP=` in the runner would pass against a half-fix that never classifies anything as a skip. It pins each skip punctuation form, the indented-continuation shape, a stderr-only skip, required-skip → ERROR, manifest drift → `required_test_missing`, failure outranking the skip WARN, empty corpus → OK/exit 0, unknown argument → exit 2 (#2057), and `.claude/worktrees/` pruning. **Guard integrity**, without which every "not counted as a pass" assertion is vacuous: `PASSED=2` must hold (a runner classifying *everything* as a skip would otherwise sail through), a **partial** skip must stay a `PASS=` and must NOT appear as `SKIP=`, a required test that passes must raise nothing, and the repo's own manifest must be non-empty with every entry present on disk. Verified by mutation against the pre-fix runner (`git show HEAD:scripts/run-skill-script-tests.sh`): **24 of 40 assertions fail**, including the headline "colon-form skip NOT reported as PASS=".
