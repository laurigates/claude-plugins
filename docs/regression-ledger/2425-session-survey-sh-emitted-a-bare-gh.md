| `session-survey.sh` emitted a bare `GH_READY=false` with no cause attached, so a consumer could not tell a transient GitHub 5xx from an expired token, a repo with no GitHub remote, or a budget kill — and `session-end`'s own guidance leans on exactly that distinction. Only the budget kill was distinguishable, via the separate `GH_TIMEOUT=true`. The four causes want four **different** responses (re-run / `gh auth login` / nothing at all / raise the budget), so a single `false` forces the consumer to guess, and the natural guess — re-run — is futile for the two most common non-transient cases. Compounding it, `gh_job` discarded each call's stderr to `/dev/null`, so the one artefact that could have classified the failure was thrown away at the source. The default per-call budget made the failure likelier than it needed to be: `SESSION_SURVEY_GH_TIMEOUT` defaulted to **4s**, but `gh pr list --author @me` resolves the `@me` handle *before* it can run the query, so the budget covers TWO round-trips — tight on a slow link or a degraded API, and every overrun silently disabled the `GITHUB_DRIFT` dedup guard. | Capture each job's stderr to a per-job `.err` file and classify `(rc, stderr)` into one `GH_FAIL_REASON=` emitted alongside every `GH_READY=false` (all three sites: `PRS`, `GITHUB_DRIFT`, and the hook summary). Classification order is load-bearing: gh's remote-less message **also** says `` `gh auth login` ``, so the no-remote test must precede the auth test or every remote-less repo reads as an auth failure and the user is sent to a login that cannot help. `137`/`143` (the watchdog's SIGTERM/SIGKILL) → `timeout`; a job set that was never launched → `no-cli` (gh absent — distinct from `auth`, since neither a re-run nor a login helps). `GH_FAIL_DETAIL=` carries the first stderr line for `api-error` and `unknown` only — the two classifications the reason alone cannot act on — sanitised (control bytes stripped, capped at 200 chars) so foreign text cannot break the `KEY=VALUE` row. Matching uses a here-string, never a pipe, so a `grep -q` closing the pipe early cannot trip `pipefail` (the #1744 SIGPIPE race).
