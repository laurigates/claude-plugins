| `health-plugin/hooks/config-drift-probe.sh` ran the analyzer with `2>/dev/null` and, on empty output, called `drift_emit` — whose empty `findings` array **is** the "checked, no drift" verdict per `hooks-plugin/hooks/lib/drift-protocol.sh`. A dead analyzer was therefore indistinguishable downstream from a clean corpus. `origin/main`'s analyzer imported nothing and could not die before producing output, so this failure class was introduced by the same PR that extracted `lib/probe.py` — a broken import fails silently, which made it the highest-risk defect in that change. The first repair gated detection on `ANALYZER_RC -ne 0` and was still wrong: an analyzer producing nothing (or non-JSON) while exiting **0** — a truncated file from an interrupted install — fell through to the same false all-clear, and the inline comment asserted the opposite of what the code did. | Key the branch on `[ -z "$OUT" ] \|\| ! jq empty` and let the exit code and stderr choose only severity and wording: `--format=json` prints unconditionally, so empty output is BY ITSELF proof the analyzer did not run. Exit 3 (bad root) is `warn`/`analyzer_bad_root`, not an analyzer failure. An unreadable corpus file is skipped and REPORTED (`corpus_unreadable`, `warn`, naming the path) rather than aborting the sweep — symlinked rules directories are normal under chezmoi/stow, and one dangling link previously cost the entire run; skipping it *silently* would have been worse, since a corpus two thirds of which failed to open would report a clean sweep.
