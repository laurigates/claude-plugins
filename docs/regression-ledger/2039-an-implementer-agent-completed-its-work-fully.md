| An implementer agent **completed its work fully** (one clean commit, clean tree) then went idle emitting only `{"type":"idle_notification","idleReason":"available"}` — its final report message was never delivered to the orchestrator. The work wasn't lost; the *communication* was, and it is intermittent (sibling agents in the same wave delivered normally — loractl post-M8 sweep, 2026-07-11). An orchestrator reading the idle as a silent exit would respawn, discarding a done task. | `parallel-agent-dispatch`'s "Handling a Missing Return" covered silent stalls (pre-commit-hook block, StructuredOutput cut-off) but not the idle-without-report communication-loss variant. The fix adds an "Idle without report (#2039)" subsection: an `idle_notification` with no preceding report is not a failure signal (run the empty-vs-dirty branch check first); recover with `SendMessage` to the named agent to resend the Return Contract (resume-from-transcript makes it cheap; a report re-request is read-only so the #1546 caveat does not apply); never respawn; brief implementers to SendMessage the report to the lead as their final act. | `scripts/check-agent-failure-contract.sh` asserts `parallel-agent-dispatch/SKILL.md` carries `Idle without report`, `idle_notification`, and `#2039` (guards I/J in `scripts/tests/test-check-agent-failure-contract.sh`). Wired into `.pre-commit-config.yaml` and `plugin-pr-checks.yml` (same entry as #1422). | issue #2039 |
