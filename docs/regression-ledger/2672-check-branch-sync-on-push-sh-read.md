| `check-branch-sync-on-push.sh` read the **checked-out** branch (`symbolic-ref HEAD`), never the push refspec destination, and computed `behind` as `rev-list --count HEAD..origin/<branch>`. Two failures fell out (#2672): (a) after `git rebase --onto origin/main <squashed-base-tip> <branch>` the pre-rebase commits on the remote are unreachable from the new tip by construction, so a lease-pinned force-push was nudged with *"N commit(s) behind … someone … pushed since your last sync. Reconcile first (git pull --rebase)"* when nobody had pushed — and that advice would re-introduce the squashed base commits; (b) the push-by-SHA protocol (`git-merge-hazards` §3) writes `<sha>:refs/heads/<other>`, so from `main` the hook exited at the default-branch exclusion and said nothing, and from any other branch it nudged about the wrong branch. | The hook now resolves the refspec **destination** (and uses the refspec source as the behind-base), suppresses the behind-nudge only for an explicit `--force-with-lease=<branch>:<sha>` whose SHA prefix-matches the freshly-fetched `origin/<branch>` tip (a **bare** `--force-with-lease` must keep nudging — the hook's own `git fetch` advances the very tracking ref a bare lease is evaluated against), and rewords any other force-push to "N remote commit(s) … are not in the commit you are pushing (expected after a rebase)" with no `git pull --rebase` advice. The semantic invariant is that the plain-push path keeps the original "someone … pushed" wording verbatim while the force-push path must not carry it. | `git-plugin/hooks/test-check-branch-sync-on-push.sh` — 10 new assertions run the real hook against a scratch repo + bare origin with a coworker push: lease matching the fetched tip → silent; stale lease / lease naming another branch / bare `--force-with-lease` / `--force` → still `ask` with the rebase wording and **without** `git pull --rebase`; plain push → `ask` retaining both the "someone … pushed" sentence and the pull advice; `<sha>:refs/heads/feature` pushed from `main` and from `other` → names `feature`; `<sha>:refs/heads/main` → still excluded. 8 of the 10 fail against the pre-fix hook. **Plus 3 assertions for the repair**: the refspec destination is adopted only when it is an unambiguous, literal branch name, because the hook sees the command as WRITTEN — `git push -u origin $(git branch --show-current)` (this plugin's own documented idiom), `git push origin "$BRANCH"`, and the multi-refspec `git push origin main feature` each resolved to a token that fetches nothing, has no `origin/<token>` (so `BEHIND=0`) and matches no PR, silencing the guard completely. All three must fall back to HEAD and still name `feature`.
