| `git-plugin/skills/deadbranch` classified branches as merged via the `deadbranch` CLI's commit-ancestry check (`git branch --merged`-style), which under-reports badly on **squash-merge** repos (the release-please / conventional-commit default): a squash collapses a branch into one fresh-SHA commit on the base, so the branch's own commits are never ancestors and it reads as **unmerged**. In one real cleanup only 4 of 28 actually-merged local branches were flagged "safe to delete"; the rest forced a `--force` (which also sweeps genuinely-unmerged work) or a hand audit. | The skill had no squash-aware reclassification. The fix adds a read-only Step 1.5 that reclassifies each `deadbranch`-unmerged branch via two deterministic signals that survive squash-merge AND later base file-drift: a `git merge-tree` no-op (merged tree equals base's tree) OR a MERGED PR for the branch head (`gh pr list --state all --head … --json state`, reading `state`/`mergedAt` per gh-json-fields.md). Reclassified branches still flow through the existing dry-run + confirmation gates. | `plugin-compliance-check.sh` `check_skill_body()` — for `deadbranch`, asserts the SKILL.md body retains both `merge-tree` and `gh pr list --state all --head` (the two reclassification signals). Dropping either would silently revert to ancestry-only detection. | issue #1869 |
