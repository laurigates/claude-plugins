| `scheduled-audits.yml`'s `docs-index` job failed on every run and the Layer-1 docs-drift audit never once executed. The label step is the job's FIRST step, so its failure skipped `Check for existing open issue`, `Run the audit script` and `Create the issue` — the run was red with none of the work attempted, and the workflow-level conclusion made the whole file look broken when its other three jobs (`agentic-audit`, `infra-compliance`, `blueprint-health`) were green. Cause: an unquoted `color: 5319e7`. The Actions runner resolves `with:` values under the **YAML 1.2 core schema**, where `<digits>e<digits>` is a float, so `gh label create` received `--color 53190000000` and answered `HTTP 422 / Label.color is invalid`. The three sibling colours in the same file survive only because each happens to contain a hex letter outside `[0-9e]` (`0e8a16`, `1d76db`, `d93f0b`), which makes the scalar unresolvable as a number — so the hazard is invisible on review and fires on roughly one colour in 250. `scripts/check-workflow-labels.sh` already owned this exact failure shape (a label step killing a job) but only asked whether a label was PROVISIONED, never whether the provisioning call would succeed. | Quoted the colour, and extended the guard to validate the colour a label create actually SENDS. **PyYAML cannot be used to do this**: it implements the YAML 1.1 resolver, whose float rule demands both a `.` and a signed exponent, so `yaml.safe_load` returns the *string* `"5319e7"` — a guard built on it reports OK on the very input that 422s in CI (measured; the first draft did exactly that and passed). The check therefore models the 1.2 core schema explicitly against the RAW source text. It also discriminates by context, which is what keeps it usable: a `with: color:` mapping value is number-resolved, while `--color 5319e7` inside a `run:` block scalar is opaque to the resolver and reaches `gh` verbatim — coercing both would report the working call site at `golden-set-evaluation.yml:109` as a defect. | `scripts/tests/test-check-workflow-labels.sh` cases **K/L/M** (33 → 49 assertions). K replays the verbatim broken shape and requires the file:line plus `SENT=53190000000` — the rendered number is the evidence, being what GitHub answered 422 to and the half a reader cannot reconstruct from the source. **L is the load-bearing counter-case**: the same token inside a `run:` block must NOT be flagged, with `COLOR_SITES=1` asserted so "not flagged" cannot pass against a scan that skipped the file. M pins the resolver's edges in both polarities — `000000` → `0` and `002200` → `2200` flagged (every leading-zero colour collapses), while `"5319e7"` quoted, `0e8a16` (unresolvable → string) and `123456` (resolves to an int that restringifies identically, so `gh` gets a valid colour) must all pass, so the fix cannot degrade into flagging every colour. **Guard integrity**: TEST A now asserts `COLOR_SITES` is non-zero on the real repo, without which every "colour is fine" assertion would hold for a checker that never looked at one.
