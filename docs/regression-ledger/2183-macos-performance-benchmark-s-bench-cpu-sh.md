| `macos-performance-benchmark`'s `bench/cpu.sh` gated PASS/WARN on a **70% multi-core scaling-efficiency floor** (`MACOS_PERF_SCALING_WARN_PCT`). Scaling efficiency (multi-core throughput ÷ *n* × single-core) only means something when every core is equivalent — false on Apple Silicon's P+E topology, where 4 of a 10P+4E machine's 14 cores run at a fraction of P-core throughput. A **healthy** 10P+4E Mac measures **24–27%**, so the benchmark WARNed on every healthy asymmetric Mac, and the WARN propagated into the run's Overall Status (`report/generate.sh` derives 🟡 from any WARN row) — a correct machine reported as degraded. Lowering the floor was rejected: no single number is simultaneously right for symmetric and asymmetric topologies, so the threshold is unfixable rather than mis-tuned. | Demoted the ratio from a gate to an **info line**: `report_scaling()` in `lib/common.sh` computes it and emits `info` only (INFO rows render in the report as ℹ️ and are excluded from the PASS/WARN/FAIL counts), annotated with the P:E split from `hw.perflevel0/1.physicalcpu` when available so the number is actionable rather than mysterious. `MACOS_PERF_SCALING_WARN_PCT` was deleted from `config.sh`, with a comment naming the issue so an exported value reads as a documented no-op rather than a bug. The **absolute** multi-core throughput is now scored via the existing self-calibrating `score_hib` baseline — a per-machine comparison carrying no cross-topology assumption — so the multi-thread section keeps a real health gate. | `macos-plugin/skills/macos-performance-benchmark/scripts/tests/test-scaling-efficiency-info.sh` (20 assertions) is SEMANTIC: it **sources `lib/common.sh` in a sandbox and executes `report_scaling()`**, asserting the emitted `summary.tsv` rows rather than grepping for the fix's wording.
