| `git-plugin:git-merge-hazards` prescribed push-by-SHA as `<sha>:<branch>` in all three of its push instructions. That short form is only accepted when `<branch>` **already exists on the remote**: the left side is a bare commit object, so git has no ref namespace to infer the destination from and refuses — `error: The destination you provided is not a full refname (i.e., starting with "refs/")` (git wraps the line right after `(i.e.,`, so triage greps the `not a full refname` fragment). The stacked-chain scenario the guidance was written from always has the child branch already pushed, which is exactly why the gap survived; it lands hardest in the **auto-close recovery** step, which explicitly opens a fresh PR from a branch that may not exist remotely yet. The error also misdirects: it names a ref the author never typed, and the skill's own zsh word-modifier warning sits two lines above, so the natural reading is that the quoting advice failed rather than that the refspec is incomplete.
