| `session-distill`'s **Cross-Repo Promotion (`[PROMOTE]`)** hand-off instructed `git -C "$PLUGINS_REPO" switch -c <branch> origin/main` and then Write/Edit **directly in the shared, long-lived local `claude-plugins` checkout**. In this portfolio that checkout is frequently contended by a concurrent Claude session, so the sequence raced: the coworker's operation **autostashed the in-flight edit** and moved `HEAD` to its own branch, and the subsequent `git add`/`commit` reported *"nothing to commit, working tree clean"* — the edit had been stashed away underneath, with no error at any step. A recovery `git worktree add` then also failed (`already used by worktree`) because `HEAD` had moved again between calls. The promote landed only via a hand-rolled isolated `git clone` (PR #2110). | The hand-off assumed exclusive ownership of a shared checkout and carried no coworker-hazard cross-references. Fix: the recipe now clones the plugins repo into a throwaway `mktemp -d` (`git clone --depth 1 --single-branch --branch main`), branches/edits/commits/pushes **there**, verifies `git log --oneline origin/main..HEAD` before pushing, and `rm -rf`s the throwaway after the PR URL is in hand. A **clone**, not a `git worktree`: a worktree registers in the shared checkout's `.git` (so it is still reachable by the contending session, and was the form observed failing), whereas a clone shares no `.git` at all.
