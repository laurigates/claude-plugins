Root cause: 21 test/hook shell scripts ran real `git -C "$VAR" init` / `git init --bare "$VAR"` against an `$(mktemp -d)` sandbox dir with no empty-value guard; when the dir resolved empty, `git -C ""` acted on the CWD (the shared main checkout). The leak is invisible — the test passes, the corruption surfaces later as "fatal: this operation must be run in a work tree". | The scripts had no `[ -n "$VAR" ]` / `\|\| exit` guard between the `mktemp -d` and the git op. Guarded all 54 sites across 21 scripts (Python tests exempt — `mkdtemp`/`tmp_path` raise, never return empty) and added a file-level linter so any future repo-targeting-git script must guard every `mktemp -d`. | `scripts/check-git-sandbox-guards.sh --strict` (+ `scripts/tests/test-check-git-sandbox-guards.sh`, 7 cases); wired into `.pre-commit-config.yaml` | issue #1692 |
