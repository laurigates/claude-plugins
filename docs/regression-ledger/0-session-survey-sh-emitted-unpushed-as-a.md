| `session-survey.sh` emitted `UNPUSHED` as a **two-line value**. `unpushed=$(git log '@{u}..HEAD' --oneline 2>/dev/null \| grep -c '' \|\| echo 0)`: on a branch with **no upstream** — any freshly created local branch, the modal session-start state — `git log` fails, so `grep -c ''` printed `0` **and exited 1**, meaning the `\|\| echo 0` ALSO ran and the value became the literal `"0\n0"`. The digest then carried a bare `0` line inside the `GIT` section, violating the `KEY=VALUE` contract (`structured-script-output.md`) and feeding a stray token into the LLM's digest. It also made `[ "${unpushed:-0}" -gt 0 ]` an unconditional false (an `integer expression expected` error swallowed by the trailing `2>/dev/null`), so **unpushed commits never contributed to `THREADS`** on a no-upstream branch. | `\| awk 'END{print NR+0}'` — always exits 0, always prints exactly one line, and needs no `\|\|` fallback at all. | `session-plugin/scripts/tests/test-session-survey.sh` TEST **V** asserts `grep -c '^UNPUSHED='` is exactly 1 **and** `grep -c '^0$'` over the whole digest is 0 (the bare-line assertion is the one that fails pre-fix; the sandbox repo is already on a no-upstream branch, so the condition arises naturally).
