| `frontmatter()` in `health-plugin/scripts/config-drift.py` ended the frontmatter block at the first `---` **substring** (`body.split("---", 2)`), not at the closing fence **line**. Every key after an inner `---` was dropped — including `paths:`, so a path-scoped rule was billed to the always-loaded budget (`always_loaded_rules` 0 → 1, measured). **118 files in this corpus already use a bare `---` line as a thematic break in prose**, and the bug fires with no block scalar at all: `description: Use the --- separator form` yields `{'description': 'Use the'}` and drops `paths`. It was latent rather than live only because no rule happened to carry an inner `---` at the time; the same commit's docstring newly advertised `description: \|` as the supported multi-line form, which is what makes it reachable. | `frontmatter()` became a line scanner with four documented properties: the block ends at the first closing fence LINE; a key is recognised only at column 0 (so a list item or a `key: value` inside a block-scalar body cannot shadow a real key); a bare-empty value stays `""` so `paths:` keeps its KEY present (consumers test presence, never truthiness); and block bodies plus indented plain-scalar continuations join with single spaces.
