They had drifted three ways, all silent. (1) `adr.schema.json` spelled the back-reference `superseded_by`; `validate-adr-frontmatter.sh` read `superseded-by` via `get_field`, so the "Superseded needs a replacement" check **never fired once** — `docs/adrs/0014` has sat `Superseded` with no back-link since March. The schema also required `date` where the hook required `created`/`modified`, and allowed 4 statuses to the hook's 7. Nothing referenced `adr.schema.json` at all: it was dead text, and a doc written from it described a document the hook would reject. (2) All three hooks read `.tool_input.content`, which **Edit does not send** (it carries `old_string`/`new_string`), so every Edit to a PRD/ADR/PRP skipped validation entirely while exiting 0 — indistinguishable from a clean document. (3) Not one ADR had frontmatter at line 1; every block sat below the H1, readable only by the hooks' own lax `awk '/^---$/{if(++n==2)exit}n'`. PRD and PRP had no schema at all. | The schema is now the only description. `scripts/check-schema.py` projects a markdown document into `{frontmatter, sections}` so **section** requirements are declared in the schema rather than in a grep loop, validates plain JSON via `--json-file`, and reconstructs the resulting document for an `Edit` payload. Severity is declared in the schema (`x-blueprint-severity: "warning"` + a `title` that becomes the message), so a missing section or a missing back-reference nudges rather than blocks per `.claude/rules/hook-block-vs-nudge.md` — a hard block would have refused edits to 20 of 22 ADRs that never had an "Options Considered". The three `validate-*-frontmatter.sh` hooks became thin wrappers over `validate-frontmatter.sh` and declare no field list. `get-validation-config.sh` reads the feature-status enum from `feature-tracker.schema.json` instead of hand-copying it, and that schema was widened to accept the **array** feature shape `blueprint-tracker-check.sh` already tolerated in a comment — a schema has to describe what the system accepts. | `blueprint-plugin/scripts/tests/test-check-schema.sh` (27 assertions) is SEMANTIC: it EXECUTES the validator, because a grep for a field name would pass against a schema nothing consumes — precisely the pre-fix state.
