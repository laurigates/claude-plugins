| `agent-patterns-plugin:cold-read-gate` did not specify **how** to run the fresh reader (synchronous vs background) or how to retrieve its critique. A session gating an upstream issue + PR body spawned the haiku reader with `run_in_background: true`; the completed background agent only emitted `idle_notification`s, a `SendMessage` asking for the critique produced another idle notification (a completed background agent's output returns as the task-completion result, not on the message channel), and the gate was abandoned — its deterministic leakage scan done by hand. | The skill's dispatch step gave the Agent template but no execution mode. Fix: Step 2 mandates **synchronous** dispatch (`run_in_background: false` — the critique IS the returned tool result), documents that a background reader's critique must be read from the **task-completion result** (never polled via `SendMessage`), and Step 4 gains an inline-deterministic-scan fallback so an unretrievable critique never blocks publication. | `plugin-compliance-check.sh` `check_skill_body()` — for `cold-read-gate` (scoped on `agent-patterns-plugin`), asserts the SKILL.md retains both `run_in_background: false` and `task-completion result`. Dropping either would silently revert to execution-mode-unspecified dispatch. | issue #2063 |
