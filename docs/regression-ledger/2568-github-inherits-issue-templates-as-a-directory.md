| GitHub inherits issue templates as a **directory**, not per file: its docs state that "if a repository defines valid issue templates **or issue template configuration** in its own `.github/ISSUE_TEMPLATE` folder, none of the contents of the default `.github/ISSUE_TEMPLATE` folder will be used." So the obvious way to add a Q&A contact link here — a lone `config.yml` — would have suppressed the whole inherited directory from `laurigates/.github`: the Bug Report template, the Feature Request template, **and** the org-wide Security contact link, which lives in the org's own `config.yml` and is therefore replaced rather than merged. The failure is silent from the repo side, which is the reason to guard it: the org files still exist, the diff shows one added file, no CI job renders the chooser, and `/issues/new/choose` requires a login so it cannot be fetched unauthenticated. GitHub's GraphQL `Repository.issueTemplates` is not an oracle either — it returned `[]` for `laurigates/.github`, which has all three files locally. | Landed the config **with local copies of both templates** rather than config-only, and re-declared the Security link in the local config. Each template carries a leading comment naming its org source and the sync obligation. | `scripts/check-issue-template-inheritance.sh` (+ `scripts/tests/test-check-issue-template-inheritance.sh`, 70 assertions) asserts the four things a local directory has to keep true: it holds at least one template rather than only configuration, it carries a config at all (**templates alone** suppress the org config, so deleting the local one drops the Security link rather than handing it back), that config re-declares the Security URL, and it still carries the Q&A diversion. Templates are identified by CONTENT, never by extension — an issue form needs top-level `name:` and `body:` keys and a markdown template needs frontmatter — because counting `*.yml`/`*.yaml`/`*.md` let a `README.md`, or a `draft: true` stub under a template's own filename, satisfy the first invariant while both real templates were deleted and GitHub rendered zero forms. A link is likewise the exact value of a `url:` key, not the URL anywhere in the file: as a free substring it read `present` for a config whose `contact_links` block was gone but which still named the URL in a comment, a trailing annotation, or an unrelated key. It is a presence-and-shape check on ONE directory and needs no network — parity with the org copies is the separate option-B drift check, deliberately not folded in. **Both polarities throughout**, since a guard that flagged every local directory would satisfy every ERROR case while being useless: CASE A (the shipped shape), CASE E (no local directory at all — the state of every other repo, where erroring would be red on arrival) and CASE K (a commented config whose links are real) must be OK, while CASES B/C/D/I/J each break exactly one invariant and assert the other findings are **not** raised, so a finding is attributable. Guard integrity: the clean cases assert `TEMPLATE_COUNT=2` and both links `present`, so a checker that opened nothing cannot pass them. Mutation-verified: `git rm`-ing both templates from the **real repo** reproduces `templates_suppressed` / exit 1 — the exact state a config-only fix would have shipped — while extension-only counting kills 10 assertions, treating no file as a template kills 19, dropping the config rule kills 2, and reverting the comment strip kills 5. That pass also found a defect in the assertions themselves: `TEMPLATE_COUNT=0` is a SUBSTRING of `NON_TEMPLATE_COUNT=0`, so an unanchored match was satisfied by a sibling key and read green against the extension-only guard (the #2219/#2297 anchoring lesson); every `KEY=VALUE` assertion is now a whole-line match. **Wiring is half the fix**: the guard ran on no CI check at all — no workflow invoked it, none runs pre-commit, and `test-skill-scripts.yml` matched no path under `.github/ISSUE_TEMPLATE/**` — so a PR deleting both templates merged green. It is now an always-on step in `plugin-pr-checks.yml` (that workflow carries no `paths:` filter because `compliance` is a required check), its self-test joined that job's `--only` list, and `.github/ISSUE_TEMPLATE/**` triggers `test-skill-scripts.yml`. | issue #2568 |
