# claude-plugins

Claude Code plugin collection providing skills and agents for development workflows.

## Project Structure

```
<plugin-name>/
├── .claude-plugin/
│   └── plugin.json      # Plugin manifest (see .claude/rules/plugin-structure.md)
├── README.md            # Plugin documentation
├── CHANGELOG.md         # Auto-generated by release-please
├── skills/
│   └── <skill-name>/
│       ├── SKILL.md     # Skill definition (user-invocable and auto-discovered)
│       └── workflows/   # Bundled *.workflow.js templates (optional)
├── hooks/               # Hook scripts, wired by plugin.json "hooks" (optional)
├── scripts/             # Helper scripts for skills and hooks (optional)
└── agents/              # Agent definitions (optional)
```

**Hooks live in many plugins, not only `hooks-plugin`.** List the plugins that declare them with `jq -r 'select(.hooks) | input_filename' */.claude-plugin/plugin.json`. A root-level `hooks.json` loads only when `plugin.json` points at it (`"hooks": "./hooks.json"`). Code that collects, filters or exports hooks scans every plugin. The safety subset exported to pi, OpenCode and Antigravity is `PI_SAFETY_ALLOWLIST` in `scripts/generate-pi-hook-extension.py`, keyed `<plugin>/<script>`.

## Git Workflow

**Commits and PR titles MUST follow conventional commit format** — `<type>(<scope>): <subject>`, scope = the plugin directory name. release-please parses them, and a squash-merge lands the PR title on `main`. Types, bumps, issue footers and merge-method detail: `.claude/rules/conventional-commits.md`.

## Local-model export

pi and OpenCode load `SKILL.md` unmodified but neither budgets the skill listing (~111 and ~88 tok/skill, uncapped); the retrieval adapter (ADR-0022) closes that gap, and `just export-opencode` survives only for subagents and hooks. Antigravity CLI registers skills in place through `skills.json`. Targets, recipes, measurements and cutover history: [`adapters/README.md`](adapters/README.md), `adapters/CUTOVER.md`, [`docs/pi-export.md`](docs/pi-export.md), [`docs/opencode-export.md`](docs/opencode-export.md), [`docs/antigravity-export.md`](docs/antigravity-export.md).

## Blueprint (constrained dogfooding)

This repo runs `blueprint-plugin` against itself in a deliberately constrained mode. State lives in `docs/blueprint/`; see `docs/blueprint/README.md` for the full rationale.

| Task | Status | Why |
|------|--------|-----|
| `adr-validate`, `sync-ids`, `feature-tracker-sync` | enabled | Read-leaning workflows that genuinely add value across this repo's ADRs, PRDs, and PRPs |
| `story-audit`, `story-reconcile` | enabled | `story-audit` is read-only and writes only its own dated artifact under `docs/blueprint/audits/`. `story-reconcile` mutates PRDs only and confirms each edit interactively. |
| `derive-plans` (subsumes former `derive-prd`/`derive-adr`), `derive-rules`, `generate-rules`, `claude-md`, `curate-docs` | disabled | Would treat plugin source as project requirements or could overwrite the hand-written `.claude/rules/` / hand-curated `CLAUDE.md` |

**Always run `/blueprint:sync-ids` with `--dry-run` first.** Each disabled task carries a `context.disabled_reason` in the manifest — read it before flipping any flag back on.

**Autonomy level 3 is consumer-only (ADR-0020, #2005).** This repo stays at `automation.autonomy_level: 1` and never runs the level-3 out-of-band pipeline. `/blueprint:autonomy-level3` scaffolds that pipeline (the `blueprint-autorun` + `blueprint-wo-execute` workflow templates + gate/parser scripts) into a *downstream* consumer repo that opts in; it is authored and tested here but not exercised here.

Blueprint bookkeeping commits are `chore(blueprint): …` and touch only `docs/blueprint/`. The `chore` type keeps the plugin unpublished, not the scope: release-please routes by files touched, so `fix(blueprint): …` on a file inside `blueprint-plugin/` **would** publish. Scope table: [`docs/blueprint/README.md`](docs/blueprint/README.md) § Commit-scope convention.

## Conventions

- Skill names: lowercase-hyphenated (`bun-development`)
- Skill invocation: lowercase with colons for nesting (`/bun:install`)
- Plugin names: suffix with `-plugin` (`typescript-plugin`)
- Use tables for quick reference (flags, options)
- Include both short and long flag forms where applicable
