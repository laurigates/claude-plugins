# Migration: v3.4 → v3.5

This document describes the migration from blueprint format version 3.4 to 3.5.

## Overview

Version 3.5 changes who writes `id_registry`, not its shape. The write-time
PostToolUse hook and the session-start `sync-ids` sweep used to be two
implementations of one registration; from 3.5 both call one engine,
`blueprint-autorun.sh --registry-reconcile` (ADR-0027 Q2/Q4 in the
claude-plugins repository). The manifest schema is unchanged.

What the engine does differently from the 3.4 writers:

| Behaviour | 3.4 (hook / sweep) | 3.5 (engine) |
|-----------|--------------------|--------------|
| `relates_to`, `github_issues` | hook: first registration only; sweep: `[]` | derived from frontmatter on every reconcile |
| `created` | hook: today's date; sweep: run timestamp | frontmatter, else the existing value, else omitted |
| Entry whose path exists but no longer carries its id (re-id'd document, removed id, junk `ADR-NNNN` from an index README) | kept forever | pruned (P1) |
| Entry whose path is missing (git-ignored work order, sparse checkout, deleted ADR) | kept | kept (P2) — the reviewed removal is `/blueprint:sync-ids` |
| `github_issues` reverse index | appended, never rebuilt | rebuilt from the entries; a work order lists itself and the PRP it `implements` |
| `last_prd` / `last_prp` / `last_trp` | raised by new registrations | max(existing, ids on disk, registry keys before pruning); never decrease |
| Concurrent writes | shared `manifest.json.tmp` (lost registrations, 0-byte manifest) | `mkdir` lock, per-PID temp file, atomic `mv` |

**Why the version is bumped.** An older plugin's drift probe compares
`format_version` against its own constant. With the bump, a clone still on the
3.4 plugin reports `format_version_drift` instead of its writers and the 3.5
engine rewriting each other's output.

## Prerequisites

- `format_version` is `3.4.0`
- `jq` available

## Migration Steps

### Step 1: Reconcile the registry once

Run the engine in check mode to see the one-time diff, then apply it:

```bash
bash <plugin-root>/scripts/blueprint-autorun.sh --registry-reconcile --check --project-dir .
bash <plugin-root>/scripts/blueprint-autorun.sh --registry-reconcile --project-dir .
```

Expect cross-refs back-filled from frontmatter, inline comments and quotes
normalised, P1 entries pruned, and counters raised over retained keys. The
diff is identical in every clone of a commit; commit it with Step 3.

### Step 2: Re-copy the vendored runner at autonomy level 3

Level 3 vendors `blueprint-autorun.sh` into `.github/blueprint/`. When that
file exists, replace it with the plugin's copy so CI runs the same engine:

```bash
if [ -f .github/blueprint/blueprint-autorun.sh ]; then
  cp <plugin-root>/scripts/blueprint-autorun.sh .github/blueprint/blueprint-autorun.sh
fi
```

### Step 3: Bump `format_version` and record upgrade history

```bash
jq '
  .format_version = "3.5.0" |
  .updated_at = (now | strftime("%Y-%m-%dT%H:%M:%SZ")) |
  .upgrade_history = ((.upgrade_history // []) + [{
    "from": "3.4.0",
    "to": "3.5.0",
    "date": (now | strftime("%Y-%m-%dT%H:%M:%SZ")),
    "changes": [
      "id_registry maintained by one engine (blueprint-autorun.sh --registry-reconcile)"
    ]
  }])
' "$MANIFEST" > "$MANIFEST".tmp && \
mv "$MANIFEST".tmp "$MANIFEST"
```

## Post-Migration Verification

```bash
# 1. format_version is 3.5.0
jq -r '.format_version' "$MANIFEST"
# Expected: 3.5.0

# 2. The committed registry is what the engine derives (exit 0)
bash <plugin-root>/scripts/blueprint-autorun.sh --registry-reconcile --check --project-dir .
```

## Rollback

```bash
jq '.format_version = "3.4.0"' "$MANIFEST" > "$MANIFEST".tmp && mv "$MANIFEST".tmp "$MANIFEST"
```

The reconciled `id_registry` is valid 3.4 data: the shape did not change.
